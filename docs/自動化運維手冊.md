# Matters 週報 / 雙週報自動化 · 運維手冊

本檔記錄本 bot **上線後的運作方式、關鍵決策、以及日常/故障處理指令**，供交接與日後查閱。
與 `CLAUDE.md`（給 AI 的架構說明）互補：CLAUDE.md 講「怎麼寫」，本檔講「怎麼跑、怎麼修」。

> 最後整理：2026-07-01。內容以倉庫實際狀態為準，如有改動請同步更新本檔。

---

## 1. 一句話現況

- **週報**：每週三早上自動組稿並**發佈到公開站**。
- **雙週報**：隔週的週三下午自動組稿並**發佈到公開站**（與週報同日、錯開時段）。
- **每日快照**：每天記錄各頻道置頂文章，累積供雙週報「置頂精選」欄使用。
- **自動發佈（2026-07-08 起啟用）**：由 `--publish`／`PUBLISH` 控制，程式**預設關閉**、週報／雙週報
  workflow 已開啟。手動觸發可在 `publish` 輸入填 `false` 只存草稿供檢視。要全面停用自動發佈，
  把兩個 workflow compose 步驟的 `--publish` 拿掉即可（回到只存草稿）。

### 端點與「讀／寫分離」（核心資料流，務必理解）
bot 可「從一個站讀、寫到另一個站」。四個環境變數（見 `bot/config.py`）：
- `MATTERS_READ_ENDPOINT`：抓資料來源，預設 `https://server.matters.news/graphql`。
- `MATTERS_WRITE_ENDPOINT`：**登入帳戶＋草稿目的地**，預設＝read（即正式站 `server.matters.news`）。
- `MATTERS_SITE`：文章連結 base，預設 `https://matters.town`（指向文章真正所在，非寫入端點）。
- `MATTERS_GRAPHQL_ENDPOINT`：back-compat；未設上述兩者時同時設定 read＋write。
- host 白名單 `ALLOWED_API_HOSTS` 只接受 `server.matters.news / .town / .icu`；打錯網址直接中止（防憑證外洩）。
- **「讀正式站、寫 icu」**：只需設 `MATTERS_WRITE_ENDPOINT=https://server.matters.icu/graphql`，read/site 留預設。
  ⚠️ 正式發佈務必**移除**此設定，否則草稿寫去 icu 測試站。

**登入方式須知**：Matters 帳戶必須「有設定密碼」（email＋密碼可登入）。若帳戶只用「email 驗證碼」
登入、從未設過密碼，bot 會登入失敗（`USER_PASSWORD_INVALID`）。→ 到 Matters 設定裡設定密碼即可。

## 3. 三個排程（GitHub Actions，時間以 UTC 定，HKT = UTC+8）

| Workflow | cron（UTC） | 對應 HKT | 說明 |
|----------|-------------|----------|------|
| `digest-weekly.yml` | `37 1 * * 3` + `37 4 * * 3` | 週三 09:37 + 12:37 | 主＋備兩次 |
| `digest-biweekly.yml` | `37 5 * * 3` + `37 8 * * 3` | 週三 13:37 + 16:37 | 主＋備，且閘到「隔週三」（14 天倍數）|
| `digest-snapshot.yml` | `0 23 * * *` | 每日 07:00 | 每日置頂快照 |

> **第 4 個 workflow `digest-test-icu.yml` 不在此表**：它**無排程**（僅手動 `workflow_dispatch`），
> 用途是「讀正式站、寫到 icu 測試站」（狀態存 `state/icu-test-pins.json`），供團隊在測試站檢視草稿。
> 需 `ICU_MATTERS_EMAIL/PASSWORD` 兩個 secret（目前**尚未設定**，要用才設）。

### 為何是「主＋備兩個冷門時段」——防漏發（重要）
GitHub 免費排程**很不準**：整點（`:00`）尤其擠，常延遲數小時、甚至**整個 run 被丟棄**。
（實例：6/24 週報表訂 02:00 UTC，實際 06:11 才跑；7/1 直接沒跑、當天草稿箱是空的。）

修法（見 commit `89c23ae`）：
1. **每次排兩個錯開的冷門時段**（`:37` 分，01 與 04 時），主時段被丟就靠備時段補。
2. **防重複**：發佈成功後在 `state/published-weekly.json` / `published-biweekly.json`（**每種各記各檔**，
   避免週報／雙週報同時跑時爭寫同一檔造成 git 衝突）記下當日 HKT 日期。
   備用時段一看「本日已發過同類」就跳過（`_already_published_today` / `_mark_published`）。
   → 就算兩個時段都跑，也**只會有一份**草稿。workflow 以 `contents: write` 把此記錄 commit 回倉庫。
   - **`--force` 例外**：手動 `workflow_dispatch`（或 CLI 加 `--force`）會**繞過**此防重複——因為手動＝刻意重推。
     排程的主／備不帶 `--force`，仍照常防重複。所以「同一天想再推一份」用手動觸發即可，不會被擋。

### 雙週報「隔週三」怎麼實現
cron 無法直接表達「每兩週」。故 cron 設「每週三跑」，compose 步驟再用 shell 閘住：
**只有當日距錨點 `2026-07-08`（上一份雙週報，週三）為 14 天的倍數才出**，中間那個週三自動跳過
（`exit 0`，**不會產生草稿**）。手動 `workflow_dispatch` 不受閘限制，隨時可測。
- 錨點與往後：7/8 → **7/22、8/5、8/19、9/2…**（每 14 天）。這些日子**週報＋雙週報同日**（週報上午、雙週報下午）。
- 要改雙週報節奏，改 workflow 的 `ANCHOR` 日期或 cron 週幾即可。

## 4. 內容與版面定案（本次上線）

| 項目 | 週報 | 雙週報 |
|------|------|--------|
| 文章標題 | `週報：Matters 一週速報 ｜ 社群熱門文章` | `雙週報：Matters 雙週回顧 ｜ 熱門文章 ＋ 編輯精選` |
| 封面標語（kicker） | `一週速報 ｜ 社群熱門文章`（無 Matters，因圖上有 logo） | `雙週回顧 ｜ 熱門文章 ＋ 編輯精選` |
| 封面主題 | `riso`（孔版·番茄紅／鈷藍） | `coral`（珊瑚紅／粉／金） |
| 封面圖說 | `圖中關鍵字由過去七日熱門文章自動擷取` | `圖中關鍵字由過去十四日熱門及置頂文章自動擷取` |
| 封面關鍵字來源 | 精選 10 篇（過去 7 日熱門） | 熱門（欄目一）＋置頂（欄目二）交錯，合共 ~10 |
| 封面日期 | 香港時間（`_today_hkt`，UTC+8） | 同左 |

- 選文演算法：合併各頻道、過去 N 日文章，按「**拍手＋留言**」排序，每作者 ≤2 篇（`MAX_PER_AUTHOR_WEEKLY=2`），
  跨頻道去重。**資格門檻：至少 1 個拍手（👏 ≥ 1）**——零拍手（留言區／自留言／bot 只靠留言衝分）不列入。
  數字透明可逐篇核對（草稿每篇都印 👏/💬）。完整準則見 `CRITERIA.md`。
- 封面程式 `bot/collage.py`，主題 `riso / earthy / coral / vintage`（每期只換關鍵字，版式自動排版）。
- 本機跑會自動讀 `.env`（`config._load_dotenv`，`setdefault` 不覆蓋雲端 secret）。

## 5. 指令速查

### 本機試跑（不影響雲端）
```bash
cd "/Users/willisho/Desktop/Matters 公司專案/newsletterbot"
python3 -m pip install -r requirements.txt

# 只組稿、不登入不發（安全）
python3 -m bot.digest --type weekly --dry-run
python3 -m bot.digest --type biweekly --dry-run
```

### 本機實發到正式站草稿箱（帳密走 .env，寫一次永久生效）
```bash
# 一次性把正式帳密寫進 .env（密碼隱藏輸入、不留 shell 歷史；.env 已被 gitignore）
printf "Matters 密碼: "; stty -echo; read PW; stty echo; echo
printf 'MATTERS_EMAIL=townweekly_ai@proton.me\nMATTERS_PASSWORD=%s\n' "$PW" > .env
unset PW; chmod 600 .env

# 只存草稿（不發佈）
python3 -m bot.digest --type weekly
# 直接發佈到公開站（加 --publish；雲端排程即是這樣）
python3 -m bot.digest --type weekly --publish
```
> ⚠️ 若 `.env` 內含 `MATTERS_WRITE_ENDPOINT=...icu...`，會寫到測試站而非正式站——正式發佈時務必移除該行。
> 想「同一天再推一份」（例如改了選文規則要重生）：加 `--force` 繞過當日防重複，
> 例如 `python3 -m bot.digest --type biweekly --force --publish`。

### 雲端手動觸發（補發 / 測試）
```bash
gh workflow run digest-weekly.yml                       # 補發並發佈（手動＝自動 --force + --publish）
gh workflow run digest-weekly.yml -f publish=false      # 只存草稿、不發佈（供檢視）
gh workflow run digest-weekly.yml -f dry_run=true       # 只跑不發（驗證 workflow）
gh workflow run digest-biweekly.yml               # 雙週報（手動不受「第一/三週一」閘、也自動 --force，可重推）

gh run list --workflow=digest-weekly.yml --limit 5    # 看最近執行
gh run view <RUN_ID>            # 看某次結果
gh run view <RUN_ID> --log-failed                     # 看失敗細節
```

### 設定 / 更新 GitHub Secrets（帳密不進對話、不留歷史）
```bash
gh secret set DIGEST_MATTERS_EMAIL --body "townweekly_ai@proton.me"
printf "Matters 密碼: "; stty -echo; read PW; stty echo; echo
printf '%s' "$PW" | gh secret set DIGEST_MATTERS_PASSWORD; unset PW

```

## 6. 常見故障排除

| 症狀 | 原因 / 處理 |
|------|------------|
| 草稿箱當天沒有週報 | GitHub 排程延遲/丟棄。主＋備＋防重複已大幅降低機率；仍漏就 `gh workflow run digest-weekly.yml` 手動補。 |
| 登入失敗 `USER_PASSWORD_INVALID` | 帳戶沒設密碼或密碼錯。到 Matters 設定設/改密碼，更新 `.env` 或 secret。 |
| 寫到了 icu 而非正式站 | `.env` 或環境有 `MATTERS_WRITE_ENDPOINT` 指向 icu；移除即回正式站。 |
| 封面沒出現 | 封面是 best-effort，失敗只會少圖不擋稿；看 log `cover generation failed`。 |
| 排程 run 顯示 `skipping` | 雙週報非「隔週三」（距 7/8 非 14 倍數）、或備用時段見「本日已發」——正常，非錯誤。 |
| 同一天已發、想再推一份 | 手動 `gh workflow run …`（自動帶 `--force`）或本機加 `--force`；防重複只擋排程備用時段。 |
| 上榜文互動很低 / 有留言區帖 | 已設「👏 ≥ 1」門檻濾掉 0 拍手文；每作者≤2 會讓多產作者的次高分文被擠掉、由他人遞補（正常，見 `CRITERIA.md`）。 |
